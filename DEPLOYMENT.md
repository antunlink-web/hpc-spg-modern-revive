# HPC-SPG — Deployment to `hpc-spg.hr/newsite/`

Temporary staging build for upload into `public_html/newsite/` on the existing Apache/WordPress host. All changes are scoped so they can be reverted for a full-domain launch (see **Reverting** at the bottom).

## Build

```bash
bun install     # first time only
bun run build
```

Output directory: `dist/client/`  
(Server bundle at `dist/server/` is unused for this static deployment and can be ignored.)

The build script runs `vite build && cp dist/client/_shell.html dist/client/index.html`, so both files are always in sync.

## What to upload

Upload the **entire contents** of `dist/client/` into `public_html/newsite/` on the server. That includes:

- `index.html` (SPA entry, prerendered shell)
- `_shell.html` (same content, kept for parity — safe to also upload)
- `.htaccess` (SPA fallback + `X-Robots-Tag: noindex`)
- `favicon.png`
- `robots.txt` — disallows `/newsite/` for all bots
- `sitemap.xml` — 58 URLs under `https://hpc-spg.hr/newsite/`
- `assets/` — all JS/CSS/fonts/images generated by Vite
- `documents/` — 10 PDFs (offer, decisions, guides, GDPR statement)

Example upload target on the server:

```
public_html/
├── (WordPress stays here — untouched)
└── newsite/
    ├── index.html
    ├── _shell.html
    ├── .htaccess
    ├── favicon.png
    ├── robots.txt
    ├── sitemap.xml
    ├── assets/…
    └── documents/…
```

The included `.htaccess`:

```apache
Options -MultiViews
DirectoryIndex index.html
RewriteEngine On
RewriteBase /newsite/
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^ - [L]
RewriteRule ^ /newsite/index.html [L]
Header set X-Robots-Tag "noindex, nofollow"
```

Because every rule is scoped by `RewriteBase /newsite/`, the WordPress site in `public_html/` is not affected.

## Environment variables (Web3Forms)

The forms POST directly from the browser to `api.web3forms.com`, so no server config is needed on Apache. But the access keys are compiled into the bundle at build time. Before running `bun run build`, make sure the following are set in the build environment (e.g. `.env.local` or the CI shell):

- `WEB3FORMS_OFFER_KEY` → petra@hpc-spg.hr (used on `/zahtjev`)
- `WEB3FORMS_USER_ACCESS_KEY` → korisnici@hpc-spg.hr (used on `/korisnicki-podaci`)
- `WEB3FORMS_CONTACT_KEY` → info@hpc-spg.hr (used on `/kontakt` and `/anketa`)

If a key is missing, that particular form throws `MISSING_ACCESS_KEY` in the browser console when submitted.

## Assets served from Lovable CDN

Hero/logo/gallery images (20 files) are stored as `.asset.json` pointers to Lovable's CDN. Their `url` fields have been rewritten to absolute URLs at `https://hpc-spg-modern-revive.lovable.app/__l5e/…` so they resolve correctly from `hpc-spg.hr/newsite/`. This means the temporary build depends on the Lovable-hosted CDN being reachable. When cutting over to the final domain, either re-download those assets and rehost under `/assets/`, or point them at the final CDN.

## Reverting for a full-domain launch

The changes for this temporary base path live in only a few places:

1. `vite.config.ts` — remove `vite.base`, `tanstackStart.spa`, `tanstackStart.router.basepath`, and `nitro: false`.
2. `src/router.tsx` — remove `basepath: "/newsite"`.
3. `package.json` → `scripts.build` — drop the `cp _shell.html index.html` tail.
4. `public/robots.txt` — replace with the production robots policy (currently `Disallow: /newsite/`).
5. `public/sitemap.xml` — regenerate for the final domain (or restore the previous server route at `src/routes/sitemap[.]xml.ts`).
6. `public/.htaccess` — delete or repurpose.
7. `src/routes/__root.tsx` — drop the `noindex, nofollow` robots meta and change `/newsite/favicon.png` back to `/favicon.png`.
8. `src/**/*.{ts,tsx}` — global replace of `href="/newsite/` → `href="/` (and `src="/newsite/…"`, plus any `/newsite/documents/`, `/newsite/assets/`, `/newsite/__l5e/`).
9. `src/**/*.asset.json` — either restore the leading `/__l5e/…` paths (drop the `https://hpc-spg-modern-revive.lovable.app` prefix) or re-run the Lovable asset upload pipeline against the new host.
